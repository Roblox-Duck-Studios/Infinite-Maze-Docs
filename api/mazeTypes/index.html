mazeTypes

common

The plain record types the maze generation passes exchange.

These live outside components on purpose. Luau has no type-only import, so a module naming components.Placement requires components at runtime, and components requires jecs — which is enough to stop a pure generation pass from loading anywhere jecs is not present, including the test runner's backend. Declaring the records here keeps rooms, features, generate and budget free of that dependency; components re-exports them so existing references keep resolving.

interface MazeConfig {
viewDistanceCells: number--

Requested detail view distance in cells.

detailRadius: number--

Detail blocks kept loaded around an observer.

detailDropRadius: number--

Distance at which detail blocks are cached out.

loadRadius: number--

Chunks generated around an observer.

unloadRadius: number--

Distance at which chunks are destroyed.

frameMs: number--

Total milliseconds per frame the whole maze pipeline may spend.

}

Streaming tuning. viewDistanceCells and frameMs are the inputs; the four radii are derived by the observers system.

There is one budget, not one per stage. Independent slices summed to more than a frame and gave no stage priority over another; a single allowance consumed in phase order means teardown outranks building, and building outranks warming caches, with no arithmetic to keep in sync.
