MazeFrame​

</>
interface MazeFrame {
deadline: number--

os.clock() value every stage stops at.

}

This frame's shared allowance, stamped once by the frame system.

Every budgeted stage stops at the same instant, so the pipeline as a whole cannot exceed frameMs no matter how the work is distributed. Stages that run late in the phase order get whatever earlier stages left, which is what makes phase order the priority order.

MazeStreaming​

</>
interface MazeStreaming {
positions: {MazePosition}--

One entry per observer, in world-cell space.

chunkFrames: {MazePosition}--

The same observers snapped to chunk coordinates.

blockFrames: {MazePosition}--

Scratch buffer reused per chunk for detail-block distance.

signature: string?--

Detail-block fingerprint of the last processed frame.

resyncNeeded: boolean--

Observers moved far enough to warrant a streaming pass.

loadsOutstanding: boolean--

The load system ran out of budget with work left.

promotionsDeferred: boolean--

The detail system hit its in-flight job cap.

}

Everything the streaming pipeline needs to know about where players are.

Each field has exactly one writer: observers writes the positions, frames, signature and resyncNeeded; load writes loadsOutstanding; detail writes promotionsDeferred. Keep it that way — the single-writer rule is what stops this becoming a hidden global again.

BuildQueues​

</>
interface BuildQueues {
demolitionOrder: {Folder}--

Folders being torn down piecewise, newest last.

demolishing: {[Folder]: boolean}--

Folders already claimed by demolition.

}

Deferred teardown, drained under a frame budget so a chunk unload never lands as one atomic hitch.

BuildAssets​

</>
interface BuildAssets {
prefabRoot: Instance--

ServerStorage.Prefab.maze, the source of every placeable model.

mazeFolder: Folder--

The workspace folder every chunk folder is parented to.

wallTemplate: Part--

Pre-styled part cloned for each wall run.

}

Shared handles the builder needs, resolved once by the bootstrap system.

These live in a component rather than as module upvalues because resolving them means waiting on ServerStorage and creating instances — work that must not happen at require time.

interface PrefabCache {
partCounts: {[Instance]: number}--

Memoized BasePart count per prefab.

warnedMissing: {[string]: boolean}--

"folder/name" keys already warned about.

}

Memoization for prefab inspection, which is pure but expensive enough that recomputing it per placement shows up in a profile.
